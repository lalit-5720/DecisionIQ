# Objectives, deviations, assumptions and screen mapping

Use this for the viva: it states plainly what was built, where, how it was checked, and what differs from the proposal.

## 2. Deviations from the proposed tools (slides 5, 9)

| Proposal | What was done | Reason / note |
|---|---|---|
| ARIMA/SARIMA, Prophet, XGBoost, LSTM | All four built. The screens also mention *DeepAR*: not built | DeepAR is not in the written proposal |
| LSTM with TensorFlow/Keras | Done, but runs in a **subprocess** | On the Windows development machine TensorFlow crashes if numpy/pandas load first; the worker imports it first |
| Isolation Forest + **autoencoder** (Keras) | Autoencoder implemented as a scikit-learn MLP (8-3-8) | Avoids a second TensorFlow dependency in the detection path; same reconstruction-error idea |
| SHAP / LIME | Exact **TreeSHAP via XGBoost's built-in `pred_contribs`**; no LIME, no `shap` package | Exact for tree models, no extra dependency |
| React.js, **Plotly**, Chart.js | React + Chart.js (no Plotly) | One charting library was enough |
| Flask / FastAPI | FastAPI | As proposed |
| **MySQL / MongoDB** | **SQLite** by default (SQLAlchemy; `pymysql` installed, MySQL untested); analytical data in CSV/Parquet files; no MongoDB | Simplicity and reproducibility for a single-machine project |
| Docker, Git/GitHub | Dockerfiles + compose; git repository initialised (not pushed anywhere) | |
| CRISP-DM, Agile | Followed in phases (see `TODO.md`) | |

## 4. Modelling assumptions that are *not* in the data
These are set in `backend/app/recommend/engine.py` (`Params`), `backend/app/simulate/engine.py` and the Settings page, and each affects specific numbers in the recommendations and simulator:
supplier lead time 3 days; 95% service level; review period 7 days; price elasticity by category (Consumer Tech -1.8, Home Appliances -1.4, Packaged Food -1.1, Ethnic Apparel -1.6, Beverages -0.9);
shelf-life windows (30-180 days) and write-off shares (20-90%); 25% annual carrying cost; marketing budget 2.5% of revenue; marketing elasticity 0.10; placeholder ROAS 3.0; festival shock +45% for 7 days; competitor shock -5%.
Forecast confidence = 100% minus the relative width of the 95% band, with the band derived from the backtest residuals.

## 5. Design screens to implemented pages

| Design screen (`docs/design/`) | Implemented page / route | Differences |
|---|---|---|
| `decisioniq_login` | Login `/login` | Real JWT sign-in; SSO buttons disabled placeholders; role tabs are a demo convenience (server decides the role) |
| `decisioniq` (dashboard) | Dashboard `/` | Units instead of rupee revenue/budget KPIs (no revenue baseline or budget exists); 10 stores instead of 12 |
| `decisioniq_data_sources_ingestion` | Data Sources `/data-sources` | File sources only (MySQL/Mongo/SAP cards not implemented) |
| `decisioniq_predictive_forecasting` | Forecasting `/forecasting` | Real model benchmark; drivers from XGBoost gain; no festival "Diwali" callout (data is not Indian) |
| `decisioniq_forecasting_states_system_variants` | Engine States `/forecasting/states` | Live state plus "preview example"; no auto-retry daemon |
| `decisioniq_risk_anomaly_detection` | Risk & Anomalies `/risk` | Statistical duplicate detection (no invoice-hash matching); no "Resolve & Refund" |
| `decisioniq_recommendations` | Recommendations `/recommendations` | Four lever types (no bundle cross-sell); CSV export instead of PDF |
| `decisioniq_what_if_simulator` | What-If `/what-if` | No "Deploy to ERP" |
| `decisioniq_explainability_model_attribution` | Explainability `/explainability` | PDP/ICE for chosen features instead of a price-elasticity curve (price is not a model input); CSV instead of PDF export |

| `decisioniq_platform_settings_governance` | Settings `/settings` | Settings marked "Applied" or "Stored only"; hash-chained audit trail; Admin user management added |
